ATS Game Loop


문서 버전: 0.1

프로젝트: Armored Tactical Simulator

상태: 기준안


1. 목적


이 문서는 ATS 전투가 한 턴 동안 어떤 순서로 진행되는지 정의한다.


ATS는 플레이어와 AI가 행동을 먼저 계획하고, 예약된 행동이 같은 시간대에 함께 처리되는 WEGO 방식의 턴제 시뮬레이션을 사용한다.


플레이어가 명령을 선택하는 시간과 전장 내부에서 시간이 흐르는 과정은 분리한다.



2. 기본 원칙




플레이어와 적 AI는 동일한 시간 안에서 행동한다.


빠른 행동은 느린 행동보다 먼저 결과가 나타날 수 있다.


명령이 예약되었다고 반드시 성공하는 것은 아니다.


이동, 관측, 사격, 위협 비행은 진행 상태를 가질 수 있다.


실제 전장 상태와 플레이어가 인지한 상태는 별도로 관리한다.


적 AI도 전장의 안개와 불완전한 정보를 적용받는다.


모든 주요 결과는 이벤트와 로그로 기록한다.





3. 턴의 의미


한 턴은 현실의 정확한 시간을 그대로 복제하지 않는다.


전투 상황과 객체 행동을 처리하기 위한 짧은 게임 시간 단위로 사용한다.


각 행동은 다음 정보를 가진다.




시작 시점


예상 소요시간


진행 상태


완료 조건


취소 조건


중단 가능 여부




예를 들어 이동은 여러 턴에 걸쳐 이어질 수 있고, 최종 목적지는 도달하거나 명령을 취소하기 전까지 유지된다.



4. 전체 턴 순서


턴 시작
→ 지속 상태 갱신
→ 플레이어 명령 입력
→ AI 상황 판단
→ 명령 검증 및 예약
→ 행동 시간순 정렬
→ 이동 처리
→ 감시·정찰 처리
→ 탐지 및 식별 처리
→ 직접화력 처리
→ 이동 위협 처리
→ 간접화력 처리
→ 피격 및 피해 처리
→ 통신 및 보고 처리
→ AI 상태 갱신
→ 전장의 안개 갱신
→ 종료 조건 확인
→ 턴 종료

7. AI 판단 단계


각 AI 객체는 자신이 알고 있는 정보만 사용해 행동을 선택한다.


AI가 실제 적 위치나 숨겨진 게임 데이터를 직접 참조해서는 안 된다.


AI 판단 입력:




현재 관측정보


마지막 관측위치


정보 신뢰도


지형


임무


현재 피해


탄약


피로


성향


주변 아군


통신 상태


예상 위협




AI는 가능한 행동을 평가하고 가장 적합하다고 판단한 행동을 예약한다.


난이도가 높아져도 적에게 실제 위치를 볼 수 있는 부당한 권한을 주지 않는다.



8. 명령 검증 단계


예약된 명령이 현재 상태에서 실행 가능한지 검사한다.


검사 항목:




이동 가능한 지형인가


통신이 연결되어 있는가


필요한 승무원이 사용 가능한가


필요한 화기가 준비되어 있는가


탄약이 존재하는가


목표가 유효한가


시야 또는 마지막 관측정보가 존재하는가


명령끼리 작업 충돌이 발생하는가




명령이 불가능하면 이유를 로그에 남긴다.


예:


주포 사격 불가
원인: 탄약수 장전 작업 미완료




9. 이동 처리


모든 이동 객체는 속도와 지형 이동비용을 적용받는다.


이동 중에는 다음이 갱신된다.




실제 위치


차체 방향


이동 이력


남은 경로


최종 목적지


노출도


관측 불이익


승무원 피로




경로 표시는 다음 세 종류로 구분한다.




지나온 경로


이번 턴 이동 구간


남은 예정 경로




한 칸 이동할 때마다 전체 경로를 삭제하지 않는다.



10. 관측 및 탐지 처리


관측은 객체 주변의 단순 원형 범위가 아니라 방향과 지형을 고려한다.


탐지 계산 요소:




관측자의 감시 능력


집중감시 여부


정찰 행동


거리


감시 방향


고도


숲·능선·건물


연막


표적의 이동


표적의 사격


은폐 상태


관측장비 손상


날씨와 시간대




탐지 결과는 단계적으로 표현한다.


미확인 접촉
→ 인원 또는 차량 추정
→ 객체 성질 추정
→ 규모 추정
→ 개별 객체 확인



사격한 객체는 섬광, 연기, 소음 또는 이동 흔적 때문에 일시적으로 노출도가 상승한다.



11. 직접화력 처리


주포


가상 사격 절차:


전차장 명령
→ 탄약수 장전
→ 포수 표적 확인
→ 포수 조준
→ 전차장 발사 통제



발사 명령:




쏴: 정확히 한 번 발사


쏴-수정: 첫 발 이후 포수가 후속 사격을 이어감


사격 그만: 표적 추적, 후속 사격, 차기 장전을 중지




사격시간 기준:




초탄 준비: 약 5초 수준


후속탄 준비: 약 5~10초 수준


승무원 피로와 기능 손상에 따라 증가




기관총




전차장기관총


포수 공축기관총


탄약수기관총




주포를 사용하지 않을 때는 승무원별 화기를 동시에 운용할 수 있다.


주포 운용 중에는:




포수는 주포 운용


탄약수는 장전


전차장은 전차장기관총 사용 가능


공축기관총 및 탄약수기관총은 제한





12. 이동 위협 처리


유도위협, 드론, 항공위협 등은 생성과 동시에 피해를 주지 않는다.


발사 또는 출현
→ 비행
→ 접근
→ 탐지 또는 경고
→ 회피·차폐 판정
→ 명중·빗나감·지형 충돌



각 위협은 다음 정보를 가진다.




현재 위치

목표


이동경로


탐지 상태


남은 거리


예상 도달시간




일반 플레이에서는 관측 수준에 맞는 정보만 표시한다.


개발자 모드에서는 전체 정보를 표시할 수 있다.



13. 간접화력 처리


간접화력은 관측 및 요청 과정이 필요하다.


포종심정찰대 처리 흐름:


아군 발견
→ 표적 성질 확인
→ 위치정보 갱신
→ 화력지원 요청
→ 요청 처리
→ 탄착 예상지역 생성
→ 포탄 비행
→ 탄착
→ 결과 관측
→ 필요 시 수정 요청



포종심정찰대는 다음 특징을 가진다.




높은 감시 능력


높은 은폐 능력


낮은 직접전투 우선도


관측이 오래 유지될수록 화력 정확도 상승


제압되거나 이동하면 요청 정확도 감소


아군이 이동하면 과거 위치에 탄착할 수 있음





14. 피격 및 피해 처리


피해는 단순 체력 감소만으로 처리하지 않는다.


피격 판정 항목:




공격 수단


공격 방향

방호 여부


기능 손상


승무원 제압


화재

사격 가능 여부


관측 가능 여부


통신 가능 여부




피격 방향은 실제 공격 위치와 표적 위치를 기준으로 계산한다.


지도에는 피격 방향 이펙트와 짧은 공격 경로 잔상을 표시한다.



15. 통신 및 보고 처리
